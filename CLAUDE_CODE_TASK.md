> **Обновлено 28.10.2026:** исходник VID-001 ранее был скачан из R2 и проверен в другой сессии Claude Code (VERIFIED, SHA-256 совпал с манифестом), но новые эфемерные сессии не сохраняют файл. **Основной способ повторного получения — защищённый загрузчик BalaGo Studio; постоянные ключи R2 Claude Code не нужны.** Для загрузчика нужна однократная настройка `STUDIO_SOURCE_TOKEN_SHA256` в Vercel Production и `STUDIO_SOURCE_TOKEN` в доверенном окружении Claude Code. Пока настройка не проведена, нужно сообщить о ней, а не автоматически требовать `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY`. После каждой новой загрузки сверять размер и SHA-256 с `lessons/003/source/manifest.json`.

## Что нужно получить

Полноценный детский анимационный урок по приложенной видеозаписи устаза. Возраст: 4–12 лет. Смысл, ход объяснения, основные примеры и выводы преподавателя должны сохраниться. Для новой озвучки использовать ElevenLabs.

Это третье занятие курса из 80 уроков. Не путай номер урока 003 с третьей сценой первого занятия. Не переноси сюда сценарии других занятий и не считай старые названия уроков подтверждением темы текущей записи.

Исходная запись: `1000218169.mp4`, 01:07:14.839, 138 938 301 байт, 640×360, H.264/AAC. Эти данные проверены технически. Полная расшифровка и смысловой разбор на этапе передачи ещё не выполнены; тему и язык записи необходимо установить по самой записи.

## Постоянный защищённый доступ через Studio (приоритет)

Уже реализован в существующем `adiletzainidinov/balago-video/apps/balago-studio`; документация: `apps/balago-studio/docs/SOURCE_ACCESS.md` в том репозитории. **Не надо добавлять R2-ключи в Claude.** В Vercel Studio уже есть R2-секреты, но до настройки машинного токена защищённый resolver возвращает 503.

После однократной настройки:
- В **Vercel Production** у существующего `balago-studio` хранится только хеш `STUDIO_SOURCE_TOKEN_SHA256` (SHA-256 от машинного токена); Production redeploy.
- В доверенном **Claude Code environment** хранится исходный `STUDIO_SOURCE_TOKEN`, не в репозитории и не в чате.
- В новом временном окружении Claude выполняй:
  ```bash
  curl -fsSL https://balago-studio.vercel.app/studio-fetch.mjs -o /tmp/studio-fetch.mjs
  node /tmp/studio-fetch.mjs adiletgpt6-beep/lesson-80 VID-001 /tmp/lesson-80-003-source.mp4
  sha256sum /tmp/lesson-80-003-source.mp4
  ```
- **Обязательно** сравни итоговый digest с доверенным манифестом: `e042aedccdda21bdd8f8eb927abd74d7c59466160983e08d3b9141350ef60876` и размер `138938301`. Загрузчик сам считает digest, но прежний VID-001 может не иметь серверного baseline.
- Если токена нет или resolver отвечает 503, попроси закончить **однократную настройку токена Studio**, а не выдавать постоянные R2-доступы. Не печатай подписанные R2-URL, bearer, JSON-ответ resolver.
- Альтернативы ниже (одноразовая подписанная ссылка, read-only R2 credentials в доверенной среде, части Git) — только запасные пути.

## Начни с источника

1. Прочитай `CLAUDE.md`, `lessons/003/BRIEF.md`, `lessons/003/STATUS.md`, [VID-001 Issue #1](https://github.com/adiletgpt6-beep/lesson-80/issues/1) и `lessons/003/source/manifest.json`.
2. **Запасной разовый путь (временная подписанная GET-ссылка):** если пользователь передал в личной сессии Claude Code краткоживущую подписанную ссылку R2 только на VID-001, скачай `1000218169.mp4` напрямую по HTTPS (curl или Python urllib); не требуй для этого `R2_ACCESS_KEY_ID` или `R2_SECRET_ACCESS_KEY`. Ссылка действует ограниченное время и сама является временным секретом: **не публикуй URL целиком в GitHub, Issues, STATUS.md, коммитах, логах и ответах; не сохраняй его в репозитории или постоянной конфигурации**. Проверь, что адрес HTTPS на `*.r2.cloudflarestorage.com` и объект оканчивается на `/balago-live-sources/live/raw/0efed512-6a0c-4900-ac57-2a97e4c6bbbd/source.mp4`; отклоняй посторонние URL. Затем проверь размер **138938301** байт и SHA-256 **e042aedccdda21bdd8f8eb927abd74d7c59466160983e08d3b9141350ef60876**. Если хеш не совпадает, не продолжай анализ. Доступ к R2 через подпись не доказывает идентичности файла без хеша.
3. **Альтернативный путь (Studio → Cloudflare R2 с учётными данными в безопасно управляемом окружении):** получи необходимые read-only R2 учётные данные в защищённом окружении (не публикуй значения и не коммить). Для загрузки из корня репозитория выполни:

   `python3 -m pip install boto3`

   `python3 scripts/download_source_r2.py`

   `python3 scripts/download_source_r2.py --verify-only`

   Для скрипта нужны `R2_ACCOUNT_ID` (или `R2_ENDPOINT_URL`), `R2_BUCKET_NAME`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`. R2 object key уже указан в манифесте и Issue #1. **Не утверждай, что эти переменные доступны, пока не проверишь окружение.** Скрипт сверяет размер, SHA-256 по доверенному манифесту и записывает локальный `lessons/003/source/1000218169.mp4`; это локальный временный файл, не Git-исходник.
4. **Резервный путь:** если приватный R2 недоступен, а 10 бинарных частей окажутся в GitHub, выполни `python3 scripts/assemble_source.py --lesson 003`; он сверит части и итоговый хеш. Если нет доступа ни к R2, ни ко всем частям, отметь конкретную причину в STATUS.md и не начинай содержательную адаптацию по догадкам. Исходные байты не изменяй.
4. Прослушай и разбери всю запись, включая вопросы, уточнения, примеры и итог, а не только начало. Если видео недоступно инструменту напрямую, извлеки аудио FFmpeg и разбей его на перекрывающиеся фрагменты, сохранив абсолютные таймкоды. Проверь отсутствие пропусков и дублей на стыках.
5. Сохрани полную расшифровку UTF-8, сегменты с исходными таймкодами и список сомнительных мест. Отдельно отредактируй читаемую версию; не заменяй ею исходную расшифровку.
6. Установи язык или языки записи. По умолчанию язык детского урока — основной язык устаза в этом видео. Русский язык задания не означает, что кыргызскую запись нужно автоматически переводить. Если запись смешанная, обоснуй выбор и сохрани смысл терминов.
7. Если инструмент распознавания не понимает кыргызскую речь, не объявляй её бессмыслицей и не строй сценарий на ненадёжной расшифровке. Укажи конкретные непроверенные интервалы и продолжай независимые технические задачи. Не подменяй содержание догадками.

## Смысл важнее украшений

Создай `lessons/003/analysis/meaning-map.csv` с полями:

`idea_id,source_start,source_end,source_statement,child_explanation,scene_ids,verification_status`

Для каждой основной мысли укажи, где устаз её объясняет, как она передаётся простыми словами, в какой сцене её увидит ребёнок и что проверено. Сохрани необходимые оговорки и причины, связывающие вывод с объяснением.

Можно убрать оговорки речи, технические паузы и буквальные повторы, не несущие нового смысла. Можно добавить бытовой пример или короткий диалог, если они помогают понять ту же мысль. Такие дополнения помечай как авторские педагогические примеры; не приписывай их устазу.

Нельзя менять позицию преподавателя, придумывать религиозные доказательства, добавлять несуществующие аяты или хадисы, превращать предположение в установленный факт. Слова на арабском, имена, цитаты и ссылки проверяй отдельно. Непроверенные формулировки не отправляй в окончательную озвучку.

## Как объяснять детям 4–12 лет

- Короткие естественные фразы, одна новая мысль за раз. Новый термин сразу объяснять знакомым примером.
- Базовый смысл должен быть понятен четырёхлетнему; старшим детям предложить дополнительные вопросы «почему?» и «как ты понял?».
- Пусть ребёнок видит действие, пример, причинную связь или простую схему одновременно с объяснением.
- Используй доброжелательного анимированного устаза как ведущего. Доска подходит для простых рисунков и коротких опорных слов. Если пример лучше понятен в действии, переходи к небольшой сюжетной сцене и затем возвращайся к выводу.
- Устаз выглядит аккуратно и уважительно, говорит спокойно, не стыдит детей. Не делай цифровую копию внешности или клонирование голоса реального человека без отдельного разрешения.
- На доске — один смысловой шаг за раз, крупно и разборчиво. Не копируй мелкий нечитаемый текст с исходной доски.
- Короткие вопросы детям с естественными паузами и последующим объяснением ответа. Не заполняй длительность пустыми паузами.
- Не изображай Аллаха в виде персонажа, человека, лица, существа, предмета или условного светящегося образа. Объясняй через слова и допустимые примеры творения. Другие спорные религиозные изображения не добавляй без основания в задании.
- Не добавляй фоновую музыку по умолчанию. Ненавязчивые звуки действий допустимы, если помогают сцене и не мешают речи.

Не сокращай часовую запись до короткого пересказа ради скорости. Сначала определи объём содержательных блоков, затем распределяй их по главам в пределах заданных 60 минут без потери существенного смысла. Результат должен быть полноценным третьим уроком; длительность каждого смыслового блока зафиксируй в сценарии.

## Требование к длительности готового видео

**Итоговый анимационный урок должен длиться ровно 60 минут (01:00:00), включая вступление и финальные кадры.** Это целевая длительность **нового готового видео**, а не исходника. Исходная запись 01:07:14.839 используется полностью для анализа. При 30 fps запланируй 108 000 кадров итоговой последовательности; проверь реальную длительность по FFprobe после сборки.

Чтобы уложиться в один час, убирай только технические паузы, словесные повторы без новой мысли и незначимые отступления. Сохрани все существенные мысли, объяснения, аргументы, оговорки, примеры, религиозные формулировки и выводы устаза. Не ускоряй искусственно ElevenLabs, не делай бессмысленных заставок и не сокращай важные блоки ради цифры. Спланируй распределение 60 минут по главам на основании полной расшифровки; итоговая сумма длительностей глав и сцен должна равняться 3600 секундам. Если эти требования вступят в объективный конфликт, документируй его в STATUS.md, не выбрасывай смысл молча и не объявляй нарушенный критерий выполненным.

## Сценарий и анимация

Подготовь сценарий с репликами, действиями, описанием доски, вопросами детям, исходными таймкодами и целевой длительностью сцен. Сохрани раскадровку и перечень визуальных материалов.

Создай настоящую 2D-анимацию: жесты и позы ведущего, смысловые действия персонажей и предметов, появление рисунков по ходу объяснения, уместные переходы. Одного движения камеры по неподвижной картинке недостаточно для всего урока.

Выбери воспроизводимый стек, подходящий текущей среде; Remotion/React допустимы. Зафиксируй версии зависимостей и команды сборки. Не трать задачу на посторонний сайт или приложение.

Формат по умолчанию: горизонтальный 16:9, итог 1920×1080, 30 fps, MP4 H.264 + AAC. Длительности сцен рассчитывай по фактической озвучке, а не растягиванием речи. Полную сборку можно рендерить по главам и затем объединять без разрывов.

## Голоса ElevenLabs

Используй ElevenLabs для новой озвучки, а не дорожку устаза поверх иллюстраций. Выбери готовый или созданный разрешённым способом голос: тёплый, спокойный, с ясной дикцией. Не клонируй голос реального устаза без отдельного согласия.

Сначала проверь текущие возможности ElevenLabs для фактического языка, выбранной модели и голоса. Сделай короткую пробу с трудными словами урока, особенно кыргызскими буквами и религиозными терминами. Проверь звучание, ударения и произношение. Не обещай качество кыргызской речи на основании одной поддержки языка в документации.

Используй `ELEVENLABS_API_KEY` и, при необходимости, `ELEVENLABS_VOICE_ID` из окружения. Сохраняй аудио по репликам, параметры и идентификаторы генераций; кэшируй результат по тексту, модели, голосу и настройкам, чтобы не расходовать баланс повторно. Перед полной генерацией оцени объём текста и расход доступной квоты. При недостаточном балансе не подключай новый платный тариф автоматически.

Если ключ, доступ или пригодная озвучка отсутствуют, подготовь остальное, запиши точную причину в STATUS.md и сообщи пользователю. Не подменяй ElevenLabs другим сервисом и не называй молчаливый ролик завершённым.

Перед завершением:

1. Проверь охват всех основных мыслей в meaning-map и соответствие реплик исходной записи.

4. Укажи фактическую длительность, разрешение, размер, язык, источники и результат смысловой проверки.
5. Честно различай «подготовлены исходники», «получен технический прогон» и «готов законченный урок». Если остаются непроверенные религиозные формулировки, перечисли их и не называй смысловую проверку завершённой.

Работай по шагам, сохраняй прогресс и продолжай доступные задачи самостоятельно. Начни с восстановления и полного разбора источника.
